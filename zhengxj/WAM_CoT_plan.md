# WAM-CoT Two-Day Project Plan

## 1. Core Idea

We study whether a VLM-based semantic planner can improve FastWAM on long-horizon RoboTwin tasks by decomposing a full task instruction into short executable subtasks.

The main hypothesis is:

> VLM decomposition alone may not help if the low-level WAM was only trained on full-task instructions. Semantic CoT becomes useful when WAM is aligned with subtask-style instructions.

Therefore, the project compares a full-task fine-tuned WAM with a subtask-aligned WAM under no-planner, open-loop planner, and closed-loop planner inference.

## 2. System Design

The system follows a hierarchical control structure:

```text
Task instruction + current image
        |
        v
VLM planner / monitor
        |
        v
Subtask instruction
        |
        v
FastWAM low-level controller
        |
        v
Robot action chunk
        |
        v
New observation
```

Roles:

- VLM: high-level task manager, progress monitor, and subtask generator.
- WAM: low-level controller that executes one instruction-conditioned action chunk.

We will test two planner modes:

- Open-loop planner: VLM decomposes the task once from the initial image.
- Closed-loop planner: VLM observes the current image after each WAM chunk and selects the next subtask.

## 3. Models

All methods should start from the same released FastWAM pretrained checkpoint trained on RoboTwin.

### Model A: FullTask-FT WAM

Fine-tune the pretrained WAM on the selected 4 RoboTwin tasks using the original full-task instructions.

Purpose:

- Serves as a fair task-specific baseline.
- Tests whether a normal WAM can execute VLM-generated short subtasks without explicit subtask training.

### Model B: SubTask-FT WAM

Fine-tune the pretrained WAM on the selected 4 RoboTwin tasks using mixed instruction data:

```text
original full-task samples + subtask-relabeled samples
```

Purpose:

- Keeps the model compatible with full-task instructions.
- Aligns the model with short subtask instructions generated by the VLM.

This mixed design is safer than training only on subtask instructions.

## 4. Experiment Matrix

Main evaluation table:

| ID | Model | Training Data | Inference Instruction | Planner |
| --- | --- | --- | --- | --- |
| A1 | FullTask-FT WAM | Full task | Full task | None |
| A2 | FullTask-FT WAM | Full task | VLM subtasks | Open-loop |
| A3 | FullTask-FT WAM | Full task | VLM subtasks | Closed-loop |
| B1 | SubTask-FT WAM | Full + subtask | Full task | None |
| B2 | SubTask-FT WAM | Full + subtask | VLM subtasks | Open-loop |
| B3 | SubTask-FT WAM | Full + subtask | VLM subtasks | Closed-loop |

Most important comparisons:

- A1 vs A2/A3: Does VLM decomposition help a normal WAM?
- A2/A3 vs B2/B3: Does subtask instruction fine-tuning make VLM decomposition more effective?
- B2 vs B3: Does closed-loop replanning improve over open-loop planning?
- A1 vs B1: Does subtask mixed fine-tuning preserve full-task performance?

Expected trend:

```text
B3 >= B2 >= A2/A3
B1 should remain close to A1
```

## 5. Task Selection

Use only 4 RoboTwin tasks because of the two-day time limit.

Selection criteria:

- Long-horizon or multi-stage.
- Baseline WAM is not already near-perfect.
- Clear gripper interaction stages.
- Subtasks are reusable across tasks.
- Subtask instructions can be generated with simple templates.

Prefer tasks with structures like:

```text
pick object -> move object -> place object
open container -> pick object -> place object into container
pick object A -> place on/near object B
```

Avoid tasks that mainly require low-level precision without semantic stage structure.

## 6. Subtask Dataset Construction

We will construct weak subtask labels from original demonstrations using gripper state transitions.

Basic assumption:

- Gripper close event: grasp or interaction begins.
- Gripper open event: release or placement happens.

For a simple pick-place trajectory:

```text
start -> close_event: pick up <object>
close_event -> open_event: move/place <object> to <target>
open_event -> end: finish/release <object>
```

For better robustness, use a small temporal margin around events:

```text
pick segment: start -> close_event + k
place segment: close_event + k -> open_event + k
finish segment: open_event + k -> end
```

Important note:

Gripper state only tells us when the interaction changes. It does not tell us the object or target names. Object and target names should come from task metadata, original instruction parsing, or manually written templates for the 4 selected tasks.

Example relabeling:

```text
Original instruction:
Put the red block into the drawer.

Subtask labels:
1. pick up the red block
2. move the red block to the drawer
3. place the red block into the drawer
```

## 7. VLM Planner Design

The VLM should not generate arbitrary language. It should select or fill simple subtask templates.

Suggested prompt:

```text
You are a high-level robot task planner.

Given:
1. The original task instruction.
2. The current camera image.
3. The list of allowed subtask templates.

Choose the next simple subtask for a low-level robot policy.
Use only one subtask at a time.
If the task is complete, set done=true.

Allowed templates:
- pick up <object>
- move <object> to <target>
- place <object> on <target>
- place <object> into <container>
- open <object>
- close <object>

Return JSON only:
{
  "stage": "...",
  "next_subtask": "...",
  "done": true,
  "reason": "..."
}
```

For open-loop planning, request a list:

```json
{
  "subtasks": [
    "pick up the red block",
    "place the red block on the blue block"
  ]
}
```

For closed-loop planning, request only the next subtask:

```json
{
  "stage": "object_grasped",
  "next_subtask": "place the red block on the blue block",
  "done": false
}
```

## 8. Metrics

Main metrics:

- Task success rate.
- Stage success rate.
- Average execution steps.
- Failure type statistics.
- VLM planning latency.

Useful failure categories:

- Wrong subtask.
- Correct subtask but WAM execution failure.
- VLM judges task complete too early.
- VLM repeats the same subtask.
- WAM cannot follow short instruction.

## 9. Ablations

Minimum ablation:

```text
correct subtask order vs shuffled subtask order
```

This tests whether the semantic subtask sequence is actually meaningful.

Optional ablations:

- Open-loop vs closed-loop.
- Full-task-only training vs mixed full/subtask training.
- Ground-truth/manual subtask list vs VLM-generated subtask list.

## 10. Two-Day Schedule

### Day 1

1. Select 4 RoboTwin tasks.
2. Run or verify pretrained FastWAM baseline evaluation.
3. Implement gripper-event-based subtask relabeling.
4. Generate subtask instruction templates for the 4 tasks.
5. Start fine-tuning Model A and Model B.

### Day 2

1. Finish fine-tuning and collect evaluation results.
2. Implement open-loop VLM planner.
3. Implement closed-loop VLM planner if time allows.
4. Run main experiments on 4 tasks.
5. Save videos for representative success and failure cases.
6. Prepare presentation figures:
   - system diagram,
   - experiment matrix,
   - success rate table,
   - stage success / failure analysis,
   - demo videos.

## 11. Fallback Plan

If training time is too long:

- Use the released pretrained WAM as the baseline.
- Fine-tune only Model B for a small number of steps.
- Focus the report on whether rapid subtask alignment improves short-instruction execution.

If closed-loop planning is unstable:

- Present open-loop VLM planning as the main result.
- Use closed-loop as qualitative demo or future work.

If VLM output is unstable:

- Use fixed task-specific subtask templates.
- Let VLM only choose the current stage from a small candidate list.

## 12. Main Claim

The final presentation should emphasize:

> Semantic CoT is not only a VLM planning problem. For hierarchical VLM-WAM control, the low-level WAM must also be instruction-aligned with the planner's subtask language. We construct a gripper-event-based subtask dataset and show that subtask-aligned WAM enables more effective open-loop and closed-loop VLM control on long-horizon RoboTwin tasks.
